# Задание 2. FURPS+ таблица требований

Требования собраны по MVP депозитного направления (интернет-банк и сайт) и кредитному направлению (онлайн-заявка на кредит). В комментарии указан источник требования: номер пункта из описания проектной работы либо пометка «дополнительное требование» с обоснованием.

| Код | Требования | Комментарий |
|-----|------------------------------------|--------------|
| F | Функциональные (Functionality) | |
| | **Депозитное направление (MVP)** | |
| | Сайт показывает список доступных депозитов с актуальными ставками | п. 1 |
| | На сайте новый клиент подаёт заявку на депозит (номер телефона и Ф. И. О.); менеджер кол-центра изучает заявку в системе кол-центра, звонит и может предложить особые условия; новый клиент приходит в отделение для идентификации | п. 1 |
| | Интернет-банк показывает список депозитов с актуальными ставками и персонализированными ставками клиента | п. 2 |
| | В интернет-банке клиент подаёт заявку на открытие депозита: счёт списания и сумма; операция подтверждается СМС-кодом | п. 2 |
| | Справочник ставок ведётся в АБС (единый источник истины вместо XLS-файлов); с ним работают сотрудники бэк-офиса депозитов и бэк-офиса кредитов | п. 2 |
| | На этапе MVP заявку на депозит обрабатывает менеджер бэк-офиса в АБС по существующему процессу согласования ставки | п. 4 |
| | Клиент получает СМС-уведомления после подтверждения размера ставки и после открытия депозита | п. 4 |
| | **Кредитное направление** | |
| | На сайте новый клиент видит предложение открыть кредит; полная информация об условиях хранится в кредитном конвейере | К п. 1 |
| | На сайте клиент подаёт заявку (телефон, Ф. И. О.); если заполняет паспортные данные — сразу получает решение на основании скоринга по данным БКИ (клиент новый, доступны только общие данные БКИ) | К п. 1 |
| | После подачи заявки на сайте клиенту приходит СМС о необходимости прийти в отделение для получения кредита и идентификации | К п. 1 |
| | При обращении в отделение сотрудник продолжает работать с той же заявкой, созданной на сайте; для полностью нового клиента создаётся новая заявка | К п. 2 |
| | В интернет-банке клиент видит список кредитов с актуальными условиями и предодобренные предложения (по клиенту уже выполнен скоринг и рассчитана сумма) | К п. 3 |
| | По заявке из интернет-банка выполняется повторный скоринг по упрощённой процедуре, если ситуация изменилась | К п. 3 |
| | Заявка на кредит из интернет-банка подтверждается СМС-кодом; клиент указывает счёт зачисления средств | К п. 3 |
| | Заявки по предодобренным предложениям обрабатываются сотрудниками в течение того же рабочего дня | К п. 4 |
| | Клиент получает СМС при изменении статуса заявки на кредит | К п. 6 |
| | **Дополнительные требования** | |
| | В АБС ведётся аудит изменений справочника ставок (кто, когда, что изменил) | Дополнительное требование. Обоснование: ставки влияют на финансовый результат и на обещания клиентам; без журнала изменений невозможно разбирать инциденты и расхождения между каналами. Функциональность дёшево реализуется в АБС, где уже есть ролевая модель |
| | Клиент интернет-банка видит текущий статус своей заявки на депозит («принята», «ставка согласуется», «ставка подтверждена», «депозит открыт») | Дополнительное требование. Обоснование: без прозрачности статуса клиенты будут звонить в кол-центр — это прямая нагрузка на 200 операторов и риск очередей после маркетинговой кампании; статус уже формируется в АБС, его достаточно отдать в онлайн-канал |
| U | Удобство использования (Usability) | |
| | Интерфейс максимально удобен для клиента; применяется система дизайна, принятая в компании: привычные цвета, брендированные элементы | п. 5 |
| | Единообразное представление продуктов и ставок на сайте и в интернет-банке (названия, форматы ставок, условия) | Дополнительное требование. Обоснование: разные формулировки и ставки в каналах породят вопросы и звонки в кол-центр; единый источник ставок в АБС делает единообразие дешёвым |
| | Процессы онлайн-заявки проектируются с учётом клиентов старшего возраста: крупные элементы, минимум обязательных полей, понятные тексты ошибок | Дополнительное требование. Обоснование: основная текущая аудитория банка — люди старшего возраста, именно они начнут пользоваться новыми каналами первыми; сложный интерфейс сведёт эффект трансформации к нулю |
| R | Надёжность (Reliability) | |
| | Все новые сервисы работают 24/7 и доступны в 99,9% случаев | п. 6 |
| | Сервисы интернет-банка доступны при сбое в ЦОД: используется резервный ЦОД, нагрузка распределяется между группами серверов и ЦОД | п. 6 |
| | Новый интеграционный слой между интернет-банком и АБС не создаёт единой точки отказа: запуск в нескольких экземплярах, отказ одного экземпляра не останавливает онлайн-канал | Дополнительное требование. Обоснование: требование 99,9% недостижимо, если весь новый трафик пойдёт через один сервис; горизонтальное масштабирование всё равно требуется по п. 6, фиксирую это явно для надёжности |
| | Допустимая рассинхронизация ставок между АБС и онлайн-каналами — не более заданного интервала (кэш ставок с TTL); в онлайн-каналах не показывается ставка, отсутствующая в АБС | Дополнительное требование. Обоснование: расхождение ставок между сайтом, интернет-банком и кол-центром — репутационный и юридический риск; правила кэширования фиксируются как контракт |
| P | Производительность (Performance) | |
| | Отклик по всем операциям онлайн-каналов — миллисекунды; устранить текущую проблему загрузки справочных данных более секунды при платежах (кэширование справочников) | п. 5 |
| | Новые сервисы поддерживают равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД | п. 6 |
| | Онлайн-нагрузка новых каналов не ложится напрямую на БД АБС (АБС масштабируется только вертикально) — обращения к АБС через интеграционный слой с кэшированием и ограничением частоты запросов | п. 6 |
| | Кредитный конвейер и система скоринга поддерживают горизонтальное масштабирование и работу 24/7 — новую онлайн-нагрузку принимают без изменений инфраструктуры | К п. 4 |
| S | Поддерживаемость (Supportability) | |
| | Во всех доработках максимально используются существующие технологии (MS SQL, Oracle); новые технологии допускаются только совместимыми с существующими платформами разработки | п. 3 |
| | Новые технологии выбираются при условии экспертизы в банке: сотрудники понимают их хотя бы на уровне языков программирования | п. 3 |
| | Для асинхронного обмена на перспективу используется Kafka; учитывать, что текущая версия платформы интернет-банка с ней несовместима | п. 3 |
| | Функционал открытия депозитов реализуется отдельно от монолита интернет-банка (микросервисный подход в рамках этой задачи), без доработки ядра платформы подрядчиком | п. 2, п. 3. СМС-функционал ядра интернет-банка требует доработки подрядчика — от него уходим, подтверждение СМС-кодом реализуем силами банка |
| | Разрабатывается документация на новые сервисы и интеграции для дальнейшего расширения системы | п. 3 |
| | Новые интеграционные сервисы разрабатываются на технологиях, которыми владеет команда АБС (Java-стек), чтобы сопровождение не зависело от одного подрядчика | Дополнительное требование. Обоснование: в команде АБС уже есть Java-специалисты, сопровождающие систему кол-центра; выбор Java Spring Boot позволяет сопровождать новый сервис силами банка |
| +R | + Ограничения (Restrictions) | |
| | Данные при передаче с сайта и из интернет-банка защищаются шифрованием трафика (TLS) — передаётся чувствительная информация | п. 1, п. 2 |
| | Прямая работа интернет-банка с API/БД АБС в новом процессе исключается | п. 6 |
| | Доработку ядра интернет-банка силами подрядчика исключаем | п. 2 |
| | АБС масштабируется только вертикально из-за своей БД | п. 6 |
| | Текущая версия платформы интернет-банка несовместима с Kafka | п. 3 |
| | Новых клиентов нельзя обслуживать без личной идентификации в отделении (проверка документов) | п. 1 |
| | Обмен АБС ↔ кредитный конвейер — раз в сутки напрямую по БД, ускорить его невозможно; этот канал не используется для новых онлайн-заявок | К п. 4 |
| | Систему скоринга нельзя нагружать дополнительными процессами по предрасчётам скорингов — предодобренные предложения формируются только на уже выполненных скорингах | К п. 5 |
| | Сотрудники бэк-офиса депозитов и бэк-офиса кредитов не имеют доступа к данным друг друга (требование безопасности); разграничение сохраняется в АБС при работе со ставками | описание процессов, п. 5 |
