## Как читать карту IT-ландшафта

- **Строки** — управления банка «Стандарт»: сеть отделений (фронт-офис), IT, бэк-офис депозитов, бэк-офис кредитов, кол-центр банка, партнёрский кол-центр, команда цифровой трансформации.
- **Колонки** — бизнес-возможности второго уровня из Business Capability Map: продажи в сети отделений, продажи через кол-центр, digital-оповещения клиентов, обслуживание депозитных процессов, обслуживание кредитных процессов, управление договорами. Возможности сгруппированы по возможностям первого уровня («Продажи и маркетинг», «Поддержка операционных процессов»).
- **В ячейках** — системы, которые реализуют соответствующую возможность для соответствующего подразделения. Цвет ячейки показывает происхождение системы: синий — разработка банка, зелёный — платформа или коробка подрядчика, оранжевый пунктир — внешняя система, жёлтый пунктир — ручной процесс (эл. почта, Excel). Пустая ячейка — возможность для этого подразделения не автоматизирована.

Ключевой вывод из карты: почти вся операционная работа замыкается на АБС, при этом критичные бизнес-возможности (расчёт и доведение ставок, продажи через партнёрский кол-центр) поддерживаются ручными процессами — эл. почтой и Excel-файлами.

## Как читать схему интеграции

- Слева — участники процессов (акторы), в центре и справа — информационные системы.
- Цвет блоков: синий — системы разработки банка, зелёный — системы на платформе/коробке подрядчика, оранжевый пунктир — внешние системы, жёлтый пунктир — ручной канал передачи ставок (почта + Excel).
- Цвет стрелок: серые — штатные интеграции; **красный пунктир** — проблемная интеграция (интернет-банк работает с базой данных АБС напрямую); **фиолетовый пунктир** — пакетный обмен «раз в сутки» напрямую через базы данных; жёлтый пунктир — ручная передача файлов.

## Описание кредитного процесса (текущее состояние)

**Участники:** клиент, менеджер отделения (фронт-офис), менеджер управления кредитных продуктов (бэк-офис).

1. **Подача заявки.** Клиент подать заявку на кредит может только в отделении. Менеджер отделения оформляет заявку в АБС (десктоп-клиент) и сообщает клиенту, что заявка будет рассмотрена банком.
2. **Передача заявки в конвейер.** Заявки из АБС попадают в Кредитный конвейер (Camunda + Oracle) **раз в сутки** через интеграцию напрямую по базе данных. Ускорить этот обмен невозможно.
3. **Рассмотрение заявки.** Менеджеры отдела кредитования работают с заявками в Кредитном конвейере. При рассмотрении конвейер по REST API вызывает систему кредитного скоринга (Python/Flask). Скоринг использует:
   - данные бюро кредитных историй — запрос по REST API **онлайн, в момент скоринга**;
   - данные о клиентах из АБС — передаются **раз в сутки** пакетно по БД;
   - внутреннюю историю оплаты кредитов: платежи хранятся в АБС, а привязка номеров платежей к кредитному договору — в Кредитном конвейере; эти данные также синхронизируются раз в сутки.
   На основании оценки от скоринга и параметров заявки сотрудник принимает решение о выдаче кредита.
4. **Выдача кредита.** При одобрении заявка получает финальный статус в конвейере, после чего **раз в сутки** эта информация передаётся в АБС, где проводятся платежи по зачислению кредитных средств на счёт клиента.

**Болевые точки процесса:**
- два звена с задержкой «до суток» (АБС → конвейер и конвейер → АБС) — именно они не позволяют выдавать решение быстрее, чем за несколько дней;
- данные для скоринга устаревают на сутки, при этом свежие данные БКИ запрашиваются онлайн;
- интернет-банк не участвует в кредитном процессе; все заявки рождаются в отделении в АБС.

## Ключевые проблемы IT-ландшафта (видны на схеме интеграции)

1. **Интернет-банк интегрирован с АБС напрямую через её базу данных** (красная стрелка) — хрупкая связка, изменение схемы БД АБС ломает интернет-банк, а нагрузка онлайн-канала ложится на перегруженную БД АБС, которая масштабируется только вертикально.
2. **Пакетные обмены «раз в сутки» по БД** между АБС, Кредитным конвейером и скорингом (фиолетовые стрелки) — лимитируют скорость кредитного процесса.
3. **Ставки по депозитам существуют только в Excel-файлах**, которые пересылаются почтой между бэк-офисом кредитов, бэк-офисом депозитов и отделениями (жёлтые стрелки) — единого источника истины по ставкам нет, ни кол-центр, ни сайт, ни интернет-банк к ним доступа не имеют.
4. **Сотрудники депозитов и кредитов не имеют доступа к данным друг друга** (требование безопасности), поэтому обмен идёт через письма — скорость согласования специальных ставок доходит до часа, клиент всё это время ждёт в отделении.
